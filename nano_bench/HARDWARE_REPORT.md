# Аппаратная проверка Nano 0.3.0 — 14 ноября 2026 UTC

## Объём и конфигурация

Проверены Arduino Nano ATmega328P через CH340 на COM79 и ADS1115 по адресу 0x48. ЭБУ, CAN, K-line и J2534 не использовались. ДПКВ не запускался; записи TPL/MCP не выполнялись. Контролируемое напряжение на A6/A7 не подавалось.

Итоговый образ прошит с verify: 13 432 байта Flash, 1 152 байта static RAM; linker сообщил 896 байт остатка под стек (не stack high-watermark). Первый кандидат размером 13 420 байт обнаружил потери при нагрузке 1000 Гц/канал; его результаты не относятся к итоговому образу. После оптимизации CRC итоговая сборка проверена отдельно. Flash записывался без EEPROM/fuses.

## Итоговые измерения

Подробный журнал: [`periodic_20261114T070700Z.jsonl.gz`](evidence/2026-11-14/periodic_20261114T070700Z.jsonl.gz), сводка [`periodic_summary.json`](evidence/2026-11-14/periodic_summary.json). В каждой receive-only фазе измеряли число вызовов transport.write: во время сбора ПК не отправлял запросы, только читал UART. START/STOP и проверки выполнялись между фазами.

| Режим | Получено | Итог журнала |
|---|---:|---|
| A6+A7, 100 Гц/канал, около 20 с | 4004 (по 2002/канал) | flags=0, разрывов native counter нет |
| Только A6, 50 Гц, около 2 с | 102 | только channel 6, потерь нет |
| Однобайтный START сохранённых параметров, около 1 с | 51 | возобновлены A6/50 Гц |
| Native 100 Гц/канал параллельно ADS 860 SPS, около 10 с | 2002 native + 8898 ADS | разрывов счётчиков нет, native flags=0, ADS flags=1 |
| A6+A7, 1000 Гц/канал, около 3 с | 6004 (по 3002/канал) | flags=0, разрывов нет |

Числа включают переходы START/STOP и доставку буферизованных сообщений и не обязаны равняться номинальной частоте, умноженной на точную длительность. На 100 Гц средний native интервал на канал — 9999.92 мкс; на 1000 Гц — 1000.03 мкс (наблюдавшиеся min/max 976/1108 мкс). При параллельном ADS/native для native 10 мс наблюдался больший джиттер, примерно 9324..10280 мкс. Это отметки `micros()` на MCU, не независимое измерение осциллографом и не гарантия жёсткого джиттера.

Итоговые RX errors / TX drops / ADC missed / I2C errors / host drops: **0 / 0 / 0 / 0 / 0**. После завершения испытаний в итоговом статусе потоки и генератор были выключены, RPM=0, COM освобождён. Это историческое состояние после прогона, не утверждение о текущем подключении или состоянии платы.

## Дополнительные проверки

- Недопустимые native masks 0/4 и периоды 0/999/10000001 отвергнуты BAD_ARGUMENT; ADS START с native 6-байтным payload — BAD_LENGTH.
- READ5, CONFIG5 и новый START5 при активном native stream отвечали BUSY без остановки потока.
- STOP5 во время ADS stream оставил ADS работающим; ADS остановили отдельным STOP. После native STOP one-shot READ5 работал, native sample_number продолжился (наблюдался 12164).
- Точный повтор того же wire/seq для START A6/50 мс примерно через 20 мс после первого образца получил cached OK и не перезапустил расписание. Последующие интервалы 49712/50004/50008 мкс; ошибок/потерь 0. См. [`start_retry.json`](evidence/2026-11-14/start_retry.json).
- EEPROM после испытаний совпала с исходным backup: [`eeprom_verify.json`](evidence/2026-11-14/eeprom_verify.json). CRC-оптимизация проверена на 6004 образцах за 3 с при 1000 Гц/канал: ошибок 0, [`optimized_crc_rate_probe.json`](evidence/2026-11-14/optimized_crc_rate_probe.json).
- CLI count-only: прежний итератор зависал, потому что вызывал неблокирующее чтение очереди вместо ожидания UART. Исправление хоста проверено: [`cli_count_smoke.jsonl`](evidence/2026-11-14/cli_count_smoke.jsonl) содержит ровно четыре события A6/A7; STOP штатно отправлен. В тестах есть fake UART проверка итератора и отсутствия ADC_READ на отсчёт.
- Исторический `offline_tests.log` сообщает 26 успешных офлайн-тестов. Два scheduler-теста являются математической моделью, не исполнением AVR-кода. Число не следует считать результатом тестирования более поздних изменений.

## Границы выводов

Входы A6/A7 не проверялись от калиброванного источника; их точность и тракт не подтверждены, плавающий вход не является тестовым сигналом. Аналоговые TPL/MCP записи и readback не проверялись. ДПКВ отдельно и параллельно не нагружался; три шаблона — reference 60-2, 36-1, 24-1, не подтверждённые паттерны Voge. Реальный 71.6-минутный wrap `micros()` не испытывался. Вся система с ЭБУ не проверялась.
