# Передача сессии: nano_bench 0.3.0

## Зафиксированные решения

- Новый изолированный модуль — прошивка 0.3.0, wire protocol 1. Источник — локальная workspace `2026-11-14_nano_adc_stream`; указана в [`PROVENANCE.json`](PROVENANCE.json). Исходный Ardu-Stim и старые журналы не изменялись. Старые Ardu-Stim/UI — legacy; новый модуль с GUI несовместим.
- UART — 1 000 000 8N1, резервная сборка 500 000. 921 600 не использовать: на 16 MHz фактический baud около 1 MHz (+8.507% к 921600).
- Основной результат — автономный native stream: один START включает расписание A6/A7, после него хост только принимает отдельные event-сообщения и завершает STOP. По умолчанию оба канала с периодом 10 мс на канал (100 Гц/канал), диапазон 1 мс..10 с. Raw значение 10-bit, reference AVCC; без калибровки нельзя считать его измерением напряжения.
- Pin/шины: A6/A7 native ADC; ADS1115 0x48 на I2C 400 kHz, ALERT/RDY D3; TPL0501 SPI до 8 MHz. Полный wire контракт и карта пинов — [`PROTOCOL.md`](PROTOCOL.md).
- Финальный образ имеет 13 432 байта Flash, 1 152 байта static RAM. Исторические аппаратные прогоны: native 4004/20 с (оба канала 100 Гц), native+ADS 2002+8898 примерно за 10 с, native 6004/3 с (1000 Гц/канал), без зарегистрированных ошибок на итоговом образе. Детали и ограничения — [`HARDWARE_REPORT.md`](HARDWARE_REPORT.md).

## Известные ограничения и безопасность

- Не проверялись ЭБУ/CAN/K-line/J2534, реальная аналоговая точность, калиброванный уровень на A6/A7, TPL/MCP выходы и ДПКВ под нагрузкой. A6/A7 могли быть плавающими. Три crank patterns — reference 60-2, 36-1, 24-1, не Voge. Не подключать ЭБУ/прочие устройства программно и не трактовать ACK/цифровую запись как подтверждение модели/физического действия.
- Scheduler soft real-time; совместный I2C/прочая нагрузка может увеличить джиттер. Реальный AVR wrap `micros()` через ~71.6 минуты не испытывался. 896 байт под стек — оценка линкера, не stack high-watermark.
- Открытие COM на проверенном CH340 сбрасывает Nano; программное снятие DTR/RTS не гарантирует предотвращение. Держать одно соединение; для гарантии через reconnect нужен аппаратный disable autoreset.
- Повтор при timeout — максимум один identical wire/seq по умолчанию; кэш платы содержит только последний запрос. При неясном ADC_READ timeout не начинать повтор новым seq.
- Исторический `offline_tests.log` сообщает 26 тестов; часть scheduler-проверок модельная. Перепроверить фактический набор тестов новой версии перед релизом, не фиксировать устаревшее число как текущий результат.

## Следующие шаги перед отдельной аппаратной работой

1. Сверить происхождение/хеши и опубликованные доказательства с [`PROVENANCE.json`](PROVENANCE.json); сохранить оригиналы без редактирования.
2. Установить `pyserial` и выполнить offline unittest discovery, включая добавленные клиентские тесты. Hardware tests запускать только отдельной явной командой и с разрешённым стендом.
3. Проверить инструменты сборки: `python tools/build.py --baud 1000000`. Загрузка — только после отдельного явного разрешения: `python tools/upload.py --port COM79 --backup-dir <path> --confirm`. Flash/EEPROM backup: `python tools/backup.py --port COM79 --output-dir <path>`. Проверить аргументы и файлы самих скриптов до аппаратного вызова; эти команды не запускались в рамках подготовки документации.
4. Сначала отдельно и безопасно проверить входной диапазон калиброванным источником и выходные устройства на стенде без ЭБУ. ДПКВ проверять только отдельным явно разрешённым этапом. Не считать завершённые исторические прогоны разрешением на новые аппаратные действия.

## Исключено из этой публикации

- X9C и интеграция/совместимость со старым GUI.
- Старый POT/free-running ADC и сценарии управления компрессией через POT.
- Автоматизированные сценарии ЭБУ и любые диагностические команды ECU.
- Аппаратные записи выходов, crank или повторный upload как часть unit tests.

## Что оставить в workspace

Не переносить в публикацию временные/генераторные артефакты и исходные копии без отдельного решения: Flash и EEPROM backups, build outputs, ELF/HEX, временные файлы, инструменты для аппаратной прошивки/считывания и исходные журналы. В частности, сохранять исходные flash-образы до/после 0.3 и предыдущий проверенный образ 0.2.0; не удалять и не переписывать резервные копии EEPROM. Опубликованные `.jsonl.gz` должны оставаться byte-identical по распакованным данным, малые JSON evidence — исходными. Подготовленные build/upload/backup скрипты и evidence не редактировать в рамках этой документационной задачи.
