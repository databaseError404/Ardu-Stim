# Nano bench 0.3.0 — автономный ADC и протокол wire 1

Изолированный модуль для Arduino Nano ATmega328P. После одного `ADC_STREAM_START` Nano сама измеряет A6/A7 и отправляет каждый результат отдельным UART-событием; ПК только принимает данные, не опрашивает каждый отсчёт. Это рабочая разработка стенда, **не подтверждённый стенд ЭБУ**. Новый модуль не поддерживает старый Ardu-Stim GUI: старые `ardustim`/UI остаются legacy и не заменяются.

## Быстрый запуск

Требуется Python и зависимость `pyserial` из [`requirements.txt`](requirements.txt). Пример для Windows:

Из корня репозитория Ardu-Stim:

```powershell
cd nano_bench
python -m pip install -r requirements.txt
python host\bench_cli.py --port COM79 nano-stream --period-us 10000 --channels 6 7 --seconds 10
```

Это 100 Гц **на канал**: каналы измеряются последовательно, не одновременно. Остановить можно также после числа сообщений: `--count N`. Команда выполняет один START, читает события, затем в `finally` посылает STOP. Для одного канала используйте `--channels 6` или `--channels 7`.

Пример API, также с одним START и без `ADC_READ` для получения отсчётов:

```python
from host.bench_client import BenchClient

with BenchClient("COM79") as stand:
    stand.nano_adc_stream_start(period_us=10_000, channels=(6, 7))
    try:
        for sample in stand.iter_events(duration=10):
            print(sample.id, sample.channel, sample.value, sample.timestamp_us)
    finally:
        stand.nano_adc_stream_stop()
```

`iter_events` выдаёт и ADS1115-события, если ADS-поток включён; различайте устройства по `sample.id` (5 — Nano, 2 — ADS1115). CLI выводит JSONL с host-monotonic меткой. `--no-reset` — best effort, не предотвращает аппаратный автосброс на проверенном CH340; для гарантии удержания состояния через открытие порта требуется аппаратно отключить автосброс. Держите одно соединение на последовательность команд.

## Кратко о возможностях и ограничениях

- UART по умолчанию 1 000 000 бод, 8N1; отдельная резервная сборка — 500 000. 921 600 не поддерживается: на 16 MHz фактический baud около 1 MHz, ошибка +8.507% относительно 921600.
- Native ADC: A6/A7, код 0..1023, опора AVCC. По умолчанию оба канала, период 10 000 мкс на канал (100 Гц). Допустимый период 1 000..10 000 000 мкс. Каждый результат — отдельное событие; после START ПК не посылает запросы на каждый отсчёт.
- ADS1115: I2C по умолчанию 0x48, ALERT/RDY на D3, I2C 400 kHz. TPL0501: SPI до 8 MHz. Возможность управления устройствами не означает, что их физическая работа или выходное значение проверены.
- Исторический аппаратный прогон итоговой прошивки: 4004 native-отсчёта за ~20 с на двух каналах; параллельно 2002 native + 8898 ADS за ~10 с; 6004 native-отсчёта за ~3 с при 1000 Гц/канал. В указанных прогонах ошибок и потерь не зарегистрировано. Это измерения MCU/протокола, не гарантия жёсткого джиттера или точности напряжения.
- Итоговая сборка: 13 432 байта Flash, 1 152 байта static RAM; 896 байт остатка по отчёту линкера — не измерение stack high-watermark. Исторические офлайн-тесты: 26; scheduler-тесты моделируют планировщик, а не выполняют код на AVR. Число тестов текущей версии может отличаться.
- ЭБУ, CAN, K-line и J2534 в проверке не использовались. ДПКВ не запускался. На A6/A7 не подавалось контролируемое напряжение; входы могли быть плавающими, калибровки и точности аналогового тракта нет. TPL/MCP физически не проверялись; их операции подтверждают цифровую запись, не движение аналогового выхода. Три шаблона ДПКВ — справочные 60-2, 36-1, 24-1, не шаблоны Voge.

## Офлайн-тесты и сборка

Из `nano_bench/`:

```powershell
python -m unittest discover -s tests -v
python tools\build.py --baud 1000000
```

При публикации прошли **30 офлайн-тестов**, включая mock-проверки предохранителей новых инструментов. Сборка переносимым скриптом воспроизвела **тот же HEX SHA-256**, что записан в Nano при аппаратной проверке: `a00963641fbded52941ac40a25895a9a1d8d7dab97d0f17303ebe463a7e2df72`. Это новая офлайн-проверка, не новый запуск оборудования.

Проверены Arduino CLI 1.0.4, Arduino AVR core 1.8.6, avr-gcc 7.3 и pyserial 3.5. Если инструменты отсутствуют, установить их нужно явно; скрипт не устанавливает core или зависимости автоматически. Например, ручная установка core: `arduino-cli core install arduino:avr@1.8.6`. Можно указать `--cli`, `ARDUINO_CLI` или поместить CLI в PATH. Каталоги `.build/`, `.cache/`, бэкапы, HEX/ELF и `__pycache__` исключены из Git.

Для сборки/загрузки/резервного копирования применяются подготовленные в модуле скрипты: `python tools/build.py --baud 1000000`; `python tools/upload.py --port COM79 --backup-dir <path> --confirm`; `python tools/backup.py --port COM79 --output-dir <path>`. Загрузка и backup — аппаратные операции, выполнять только при отдельном явном разрешении. Исторические отчёты и сохранённые бэкапы сами по себе не означают, что устройство сейчас подключено или находится в том же состоянии. Переносимые backup/upload проверены только mock-тестами; при публикации к оборудованию не обращались. Перед аппаратной операцией отключить ЭБУ/силовые нагрузки: открытие COM и загрузка сбрасывают Nano и меняют GPIO.
